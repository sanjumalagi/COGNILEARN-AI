# 1. Introduction

The AI Prompt Model defines how structured educational information is transformed into prompts for Large Language Models (LLMs).

Rather than allowing an AI model to independently determine instructional strategies, CogniLearn AI first constructs a structured teaching context using the Educational Intelligence layer. The AI Prompt Model then converts this teaching context into a standardized prompt that any supported AI provider can understand.

This approach ensures consistent, explainable, and provider-independent AI-assisted teaching.

---

# 2. Objectives

The AI Prompt Model aims to:

- Standardize prompt generation.
- Support multiple AI providers.
- Preserve educational reasoning.
- Generate consistent instructional content.
- Reduce prompt engineering complexity.
- Improve response quality.
- Enable explainable AI interactions.

---

# 3. Role within CogniLearn AI

The AI Prompt Model answers the following question:

> **"How should educational context be communicated to an AI model?"**

It converts structured teaching information into a prompt while ensuring that educational decisions remain unchanged.

# 5. Prompt Components

Every prompt consists of several structured components.

| Component | Purpose |
|-----------|---------|
| System Prompt | Defines AI behavior |
| Teaching Context | Educational information |
| Learner Context | Learner profile summary |
| Learning Objective | Target outcome |
| User Request | Current learner query |
| Response Instructions | Required output format |

---

# 6. System Prompt

The System Prompt defines the AI's instructional role.

Example responsibilities include:

- Act as an educational tutor.
- Follow the provided teaching strategy.
- Avoid introducing unrelated topics.
- Explain concepts clearly.
- Encourage conceptual understanding.
- Provide accurate educational content.

The System Prompt remains independent of any specific learner.

---

# 7. Teaching Context

Generated by the Teaching Engine.

Example fields:

| Attribute | Description |
|-----------|-------------|
| Current Topic | Topic being studied |
| Teaching Strategy | Instructional approach |
| Difficulty | Target difficulty |
| Learning Objective | Desired outcome |
| Weak Concepts | Areas requiring attention |
| Current Mastery | Learner mastery estimate |

This context represents the educational intent of the lesson.

---

# 8. Learner Context

The Learner Context personalizes the prompt.

Example information includes:

- Ability estimate (θ)
- Topic mastery
- Previous assessments
- Current learning path
- Recommendation
- Previous AI interactions

Only relevant information is included to avoid unnecessary prompt complexity.

---

# 9. User Request

The learner's current request is appended without altering the educational context.

Examples:

- Explain Binary Search.
- Give another example.
- Create practice questions.
- Provide a hint.
- Summarize the topic.

---

# 10. Response Instructions

The AI receives explicit instructions regarding the expected response.

Examples include:

- Explain step-by-step.
- Use simple language.
- Generate exactly three practice questions.
- Do not reveal answers immediately.
- Return Markdown format.
- Include a concise summary.

These instructions ensure consistent AI output.

# 12. Prompt Template

A standardized prompt consists of:

```
System Prompt

↓

Teaching Context

↓

Learner Context

↓

Learning Objective

↓

Current User Request

↓

Response Instructions
```

This modular structure simplifies prompt generation and maintenance.

---

# 13. Prompt Validation

Before sending a prompt to an AI provider, the system validates:

- Required fields are present.
- Teaching context exists.
- Learner information is complete.
- Prompt length is acceptable.
- No sensitive information is included.
- Response instructions are defined.

Invalid prompts are rejected before AI invocation.

---

# 14. AI Provider Independence

The AI Prompt Model is independent of any specific AI provider.

Supported providers may include:

- Google Gemini
- OpenAI GPT
- Anthropic Claude
- Meta Llama
- Mistral
- DeepSeek

Only the AI Service Layer handles provider-specific API communication.

---

# 15. Response Expectations

The AI should generate:

- Accurate explanations.
- Personalized instruction.
- Worked examples.
- Practice questions.
- Hints.
- Revision summaries.

Educational decisions must never be modified by the AI.

---

# 16. Relationship with Educational Intelligence

| Component | Role |
|-----------|------|
| Teaching Engine | Creates teaching context |
| AI Prompt Model | Builds structured prompt |
| AI Service Layer | Sends prompt to provider |
| Large Language Model | Generates instructional content |

This separation ensures that Educational Intelligence remains the decision-maker.

---

# 17. Design Characteristics

The AI Prompt Model is:

### Structured

Uses standardized prompt sections.

### Explainable

Every prompt originates from educational evidence.

### Provider-Independent

Supports multiple AI providers.

### Reusable

Prompt templates can be reused across lessons.

### Secure

Prevents sensitive learner data from being exposed.

---

# 19. Summary

The AI Prompt Model standardizes communication between the Educational Intelligence layer and Large Language Models. By transforming structured teaching contexts into consistent prompts, it enables personalized, explainable, and provider-independent AI-assisted instruction.

This design preserves the separation between educational reasoning and AI content generation, ensuring that the AI model functions as an instructional content generator rather than an educational decision-maker.

---

# Guiding Principles

> Educational reasoning must precede prompt generation.

> Prompts should communicate structured teaching context.

> AI providers should remain interchangeable.

> Prompt generation should be explainable and reusable.

> Sensitive learner information should never be exposed unnecessarily.

> Educational Intelligence drives Teaching Intelligence.
